## 로어 조각이란

작품 속에서 **세계에 대해 이야기를 들려주는 한 덩어리 글**. 예:
- 게임: 불가사의를 지으면 뜨는 글과 백과사전 항목, 유물·유적 설명, 사건(이벤트) 이야기와 그 연쇄, 고고학 발굴 이야기, 탐사 이상 현상, 승리·결말 이야기, 기술마다 붙은 인물의 말, 진영·기원 소개 글, 기록(코덱스·일지).
- 소설·영상: 작품 안에 나오는 문서·기록(백과사전 인용, 역사서, 일지), 이야기 속 전설·신화, 장마다 붙은 머리글.
- **작품이 마련해 둔 것은 빠짐없이** 모은다(불가사의라면 전부, 고고학 유적이라면 전부). 수가 너무 많은 갈래(기술 인용 수십 개 등)는 하나씩 짧게라도 다 넣는다.
- ★**대사·인용도 빠짐없이**(2026-10-22 진님: "문명류 게임은 로어에 그 뭐랄까.. 대사 같은게 적히거든? 그런것도 적어야해. 다른 작품들도 마찬가지야"). 기술 인용, 불가사의·프로젝트 인용, 지도자·진영의 대사(인사·선언·승리), 장 머리글처럼 작품이 인물의 말로 세계를 들려주는 것은 하나하나 조각으로 둔다. 원문은 저작물이라 싣지 않는다 — 누가·언제 뜨는지·무슨 말인지를 우리말로 적고, 그 대사를 들을 수 있는 영상이 있으면 `videos` 로 건다(아래 '영상 고리'). 작품마다 원자료의 대사 수와 조각 수를 맞춰 보고 빠진 것을 채운다.

## 만들 파일

`data/lore/<작품 id>.json` — `{"lore": [ ... ]}`

```json
{
  "id": "wonder_mind_flower",          // 영문 소문자_밑줄, 작품 안에서 겹치지 않게
  "ko": "…",                           // 그 조각의 이름(불가사의 이름, 사건 제목 등) — 한글 표기 규칙 그대로
  "orig": "Mind Flower",
  "ko_status": "공식",                  // 공식 | 우리 표기
  "ko_check": "원자료",                 // 공식일 때만
  "ko_src": "…",
  "kind": "불가사의",                   // 불가사의 · 유물 · 유적 · 사건 · 기록 · 인용 · 대사 · 결말 · 전설 · 소개 가운데
                                        // 인용 = 기술·불가사의·장 머리글에 붙은 인물의 말(책 이름이 붙는 것), 대사 = 게임·작품 안에서 인물이 직접 하는 말(외교 인사·선언·무전 등)
  "where": "…",                         // 작품 어디서 나오나 — 예: '불가사의를 지으면 뜨는 글과 백과사전 항목'
  "speaker": "…",                       // 말하는 인물이 있으면 그 이름(없으면 빈 문자열). 인물 이름은 여기와 요약 안에서는 써도 된다
  "summary": "…",                       // 무슨 이야기인지 우리 말로 새로 쓴다. 3~8문장, 700자 안쪽
  "reveals": "…",                       // 이 조각으로 세계에 대해 알게 되는 것 한 줄(60자 안쪽)
  "terms": ["mind_flower"],             // 이어지는 이 작품 용어 id (data/terms/<id>.json 에 있는 것)
  "concepts": ["living_planet"],        // 이어지는 개념 id(가장 좁은 것, 확실할 때만)
  "spoiler": false,                     // 요약이 반전을 터뜨리면 true
  "refs": ["https://…"]
}
```

- 로어에 나오는 중요한 것이 용어 사전에 없으면(불가사의 하나가 빠졌다든가) `data/terms/<id>.json` 끝에 **더해도 된다**(지침의 칸 그대로). 이미 있는 용어는 고치지 않는다.

## 쓰기 규칙 — 가장 중요

- **원문을 옮기지 않는다.** 불가사의 글·인물의 말·사건 글은 저작물이다. 문장을 베끼거나 번역해 싣지 않는다. 짧은 인용도 넣지 않는다. 읽고 이해한 뒤 "누가, 무엇을, 왜 말하는지, 그래서 세계의 무엇이 드러나는지"를 우리 말로 새로 쓴다.
- ★**짧은 글(인용·대사·몇 문장짜리 설명)은 문장마다 따라 옮겨 쓰지 않는다** — 그러면 사실상 번역이 된다. '누가, 무엇에 대해, 어떤 생각을 말하는가'를 한두 문장으로 적고, 그 글이 세계에 대해 알려 주는 것을 덧붙인다. 긴 글(백과사전 항목·막간 이야기)도 장면을 차례로 다시 들려주기보다 무엇이 드러나는지를 중심으로 줄인다.
- 쉬운 우리말로, 영어 낱말을 섞지 않는다(고유 이름은 예외).
- 확실하지 않은 내용은 쓰지 않는다. 판마다 다르면 기준 판을 따르고 그렇다고 적는다.
- 반전이 드러나는 조각은 `spoiler: true`, 그런 조각은 `ko_src`·`where` 에도 반전을 적지 않는다.

## 자료

- 게임은 게임 문자열(정식 한국어 문자열, 없으면 영어 문자열)이 가장 좋은 자료다. 맡은 작품의 `works_parts` 의 `ko_sources` 에 처음 조사 때 쓴 통로가 적혀 있다(공개된 문자열 사본·백과사전 문서 등) — 거기서 시작한다.
- 나무위키·해외 팬 위키(Fandom 등)·위키백과는 이해와 원어 확인에 쓴다. 정식 한국어 표기가 없으면 나무위키 통용 표기를 따른다(research_brief.md 규칙).
- `docs/research_brief.md` 의 '자료를 찾는 길'과 '지킬 것'을 그대로 지킨다: 개인 정보(이름·전자우편)를 어떤 요청에도 넣지 않는다, 처음 여는 사이트는 robots.txt 를 **따로 먼저** 보고 막으면 열지 않는다, `api.steampowered.com` 은 쓰지 않는다, 봇 확인 화면은 풀지 않는다, 파일을 내려받아 실행하지 않는다.
- 임시 파일은 스크래치 폴더 안 `lore_<작품 id>` 하위 폴더에.

## 영상 고리

작품·용어·로어 조각에 맞는 유튜브 영상을 보면 `videos` 칸에 건다 — 규칙은 `docs/survey_brief.md` 의 '영상 고리' 절 그대로(정식으로 올라온 것만, 본편 통째 업로드 금지, 유튜브 검색 화면 열지 않기, oembed 로만 확인).

- 알려 줄 것(짧게): 갈래별 조각 수, 표기(공식 원자료·2차·우리 표기) 수, 더한 용어, 쓴 자료, 못 찾았거나 뺀 것.
