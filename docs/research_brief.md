# 작품 하나 조사 지침

작품 하나를 맡아 그 작품의 핵심 용어를 정리하고, 이 사전의 개념에 잇는다.
레포 루트는 `C:\Users\jin0x\dev\sandbox\sf-lexicon`. 먼저 `CLAUDE.md` 와 `data/concepts.json` 을 끝까지 읽는다.

## 만들 파일 셋

1. `data/terms/<작품 id>.json` — `{"terms": [ ... ]}`
2. `data/works_parts/<작품 id>.json` — 작품 소개 한 건 (아래 '작품 칸' 절)
3. `data/concept_proposals/<작품 id>.json` — 개념 사전에 없어서 못 이은 것이 있으면 `{"proposals": [{"ko", "en", "cat", "one", "why", "terms": [용어 id]}]}`. 없으면 `{"proposals": []}`.

다 쓰면 `PYTHONUTF8=1 python scripts/check.py` 를 돌려 **내 작품 파일에서 나온 틀린 곳이 0** 이 될 때까지 고친다.
(작품 소개는 내가 works.json 에 합치니, works.json 이 없어서 생기는 말은 무시해도 된다.)

## 무엇을 고르나 — 세계 크기에 맞춰

- 세계가 **큼**이면 50~100개, **중간**이면 30~60개, **작음**이면 15~30개(맡긴 글에 크기를 적어 준다). 억지로 채우지 않는다.
- 넣는 것: 세력, 종족·생물, 존재(신적 존재·행성 의식처럼 사람 아닌 홀로인 것 — 인물은 아님), 기술·물건, 장소, 사건·시대, 제도·직위, 현상·힘.
- **개념에 이어지는 것을 먼저**, 그다음 그 작품 세계를 이해하는 데 꼭 필요한 것.
- **인물은 넣지 않는다.** 칭호·직위가 곧 개념인 것(예언된 구원자의 칭호 같은 것)만 넣는다.
- 기준으로 삼을 판(어느 책·시리즈·게임까지)은 맡긴 글에 적어 준다. 적혀 있지 않으면 원작과 원작자가 이은 정식 후속작을 기준으로 삼고, 그 범위를 작품 칸 `scope` 에 적는다. 그 밖의 파생작은 넣지 않는다.

## 용어 한 건의 칸

```json
{
  "id": "holtzman_shield",            // 원어에서 딴 영문 소문자_밑줄
  "ko": "…",                          // 한글 표기 (아래 규칙)
  "orig": "Holtzman shield",          // 원어 (일본어·중국어 작품은 원어 그대로, 영어 표기가 널리 쓰이면 orig_en 칸을 더해도 된다)
  "ko_status": "공식",                 // "공식" | "우리 표기"
  "ko_check": "원자료",                // 공식일 때만: "원자료" | "2차 자료"
  "ko_src": "…",                      // 공식일 때 어디서 확인했나 — 판·쪽·화면·주소를 구체적으로
  "alt_ko": [{"ko": "…", "src": "…"}],// 다른 공식 표기(책과 영화가 다르거나 옛 판과 새 판이 다를 때)
  "kind": "기술·물건",
  "concepts": ["energy_shield"],      // 이 용어가 해당하는 개념 id. 가장 좁은 것만. 맞는 게 없으면 []
  "one": "…",                         // 한 줄, 40자 안쪽
  "note": "…",                        // 2~3문장, 200자 안쪽. 이 작품에서 어떻게 작동하나
  "spoiler": false,                   // 설명 자체가 줄거리를 터뜨리면 true
  "refs": ["https://…"]               // 참고한 곳
}
```

## 한글 표기 규칙 — 가장 중요

- **기억으로 짓지 않는다.** 한 건 한 건 찾아서 확인한다. (이 일을 하는 우리 쪽 판정이 기억에 기대면 절반 넘게 틀렸던 기록이 있다.)
- 공식 = 정식 한국어판에 그렇게 나온다: 책 번역판, 게임 한국어판(화면·공식 사이트·패치 안내), 정식 자막·더빙, 공식 한국 홍보물.
  - `ko_check: "원자료"` — 그 정식판 자체(공식 사이트 문장, 게임 문자열, 출판사 책 소개·미리보기, 정식 자막 화면 등)에서 직접 봤다.
  - `ko_check: "2차 자료"` — 위키·블로그가 "정식판에서는 이렇게 옮겼다"고 전하는 것을 봤다. 어느 문서인지 `ko_src` 에 적는다.
- 공식 표기를 끝내 못 찾으면 `ko_status: "우리 표기"` 로 둔다. 공식인 척하지 않는다.
  - 이때 `ko` 는 먼저 **국내 팬들이 실제로 쓰는 이름**을 찾아 따른다: 나무위키 문서 제목·본문, 국내 팬 위키·커뮤니티. `ko_src` 에 "나무위키 '문서 이름' 문서에서 통용되는 표기"처럼 어디서 봤는지 적는다.
  - 쓰는 이름이 여럿이면 가장 널리 쓰이는 것을 `ko` 로, 나머지를 `alt_ko` 에(출처와 함께).
  - 국내에서 쓰는 이름이 아예 없을 때만 원어를 소리 나는 대로 적거나 원어 그대로 둔다. 그때 `ko_src` 는 "국내 통용 표기 없음 — 원어를 소리 나는 대로".
- 정식판이 여럿이면 `ko` 는 **가장 최근에 나온 정식판** 표기로, 나머지는 `alt_ko` 에 출처와 함께.
- 위키 두 곳이 같은 말을 해도 서로 베꼈을 수 있다. 원자료를 하나라도 찾는 것이 낫다.
- **게임 문자열을 사본으로 봤을 때**(게임을 깔지 않고 누군가 올린 게임 파일 사본을 읽음): 정식 통로(상점 한국어 소개문·공식 사이트 등)의 표기 몇 개와 대조해 같으면 원자료로 친다. `ko_src` 에 파일 이름·키와 함께 사본이라는 것을 적고, 작품 칸 `ko_sources` 에 사본 주소와 대조한 결과를 적는다.
- **같은 정식판 안에서 이름이 둘이면**(정식 이름과 줄인 이름 등) `ko` 는 이름으로 쓰이는 쪽, 다른 것은 `alt_ko` 에 어디서 쓰는지와 함께.
- **정식판이 원어와 뜻을 다르게 옮겼으면** 공식 표기를 그대로 쓰고, 그 차이를 `note` 에 한 줄로 적는다.
- 게임의 선택지(정부 형태·윤리관 같은 사회 짜임)는 `제도·직위`, 배경 이야기를 고르는 선택지(기원 등)는 그 내용에 맞는 갈래로.

## 작품 칸 — `data/works_parts/<작품 id>.json`

```json
{
  "id": "stellaris",
  "ko": "스텔라리스",                  // 작품의 한국어 이름
  "ko_status": "우리 표기",            // 정식 한국어 제목이면 "공식", 정식판이 원제를 그대로 쓰거나 못 찾았으면 "우리 표기"
  "ko_src": "…",                      // 공식이면 어디서 봤나
  "orig": "Stellaris",
  "orig_en": "",                      // 원제가 영어가 아니면 영어 공식 제목
  "media": ["게임"],                   // 소설 · 영화 · 드라마 · 애니메이션 · 만화 · 게임 · 탁상 게임
  "year": 2016,                       // 처음 나온 해
  "by": "…",                          // 지은이·감독·만든 곳
  "scope": "…",                       // 어디까지를 기준으로 했나, 한글 표기를 어디서 가져왔나
  "one": "…",                         // 작품 소개 한 줄(줄거리를 터뜨리지 않게)
  "ko_sources": [{"what": "…", "url": "…"}]   // 쓴 정식 한국어판과 확인 근거
}
```

## 글쓰기 규칙

- **남의 글을 옮기지 않는다.** 위키·공식 설명문의 문장을 베끼거나 번역해 옮기지 않는다. 읽고 이해한 뒤 우리 말로 새로 짧게 쓴다. 인용하지 않는다.
- 쉬운 우리말로 쓴다. 영어 낱말을 섞지 않는다(용어 자체는 예외).
- `spoiler: true` 인 용어는 `ko_src`·`alt_ko` 의 출처 글에도 반전을 적지 않는다(근거 글에 정체를 밝히는 인용을 넣지 말 것).
- 확실하지 않은 사실은 쓰지 않는다. 판마다 설정이 다르면 기준 판의 것을 쓰고, 다른 판 이야기는 하지 않는다.

## 개념 잇기 규칙

- `concepts.json` 의 `one`·`note` 를 읽고, 그 용어가 **정말로 그 개념의 한 예일 때만** 단다. 이름이 비슷하다고 달지 않는다
  (예: 어떤 작품의 '워프'가 정신의 차원이면 공간 왜곡 추진이 아니라 또 하나의 차원).
- 하위 개념이 맞으면 하위만 단다(상위는 화면이 묶는다). 상위와 하위를 같이 달면 점검에서 걸린다.
- 한 용어가 두 개념에 다 해당하면 둘 다 단다.
- 맞는 개념이 없지만 다른 작품에도 있을 법한 생각이면 `concept_proposals` 에 올린다. 그 작품에만 있는 고유한 것이면 그냥 `concepts: []`.

## 자료를 찾는 길 (첫 묶음 18작품에서 배운 것)

- **웹 검색 한도는 동시에 도는 조사들이 함께 쓴다(한 차례 200회 남짓).** 검색은 아끼고, 아는 주소는 바로 연다.
- 소설: 리디북스 미리보기 본문, 구글 북스 본문 검색(연달아 하면 로봇 확인이 뜬다 — 천천히, 뜨면 풀지 말고 멈춘다), 알라딘·예스24 책 소개.
- 게임: 게임 한국어 문자열 파일(설치본이나 공개된 사본), 스팀·PS·닌텐도 한국 상점 페이지, 공식 한국어 사이트·패치 안내. 마이크로소프트 상점의 언어 목록은 틀리게 나오니 근거로 쓰지 않는다.
- 영상: 자막을 직접 볼 길이 없으면 정식 서비스(디즈니+·넷플릭스·티빙·라프텔·웨이브 등)의 작품·회차 소개문이 원자료다. 국내 개봉 제목은 영화진흥위원회 KOBIS.
- **나무위키**: 표기는 정식판과 다른 경우가 많았다(듄에서 8곳). 정식 표기의 근거로는 2차 자료로만 쓰고, 정식 표기가 없을 때는 통용 표기의 근거로 쓴다(위 규칙). 설정을 이해하는 데도 써도 된다. 문서 주소는 `https://namu.wiki/w/<문서 이름>`(robots.txt 가 `/w/` 를 허용).
- **해외 사이트**: 설정을 이해하고 원어 이름을 확인하는 데 쓴다 — 영어·일본어·중국어 위키백과, 작품별 팬 위키(Memory Alpha·Wookieepedia·Lexicanum·Halopedia 같은 Fandom 위키), ISFDB, TV Tropes, 일본 작품은 일본어 공식 사이트·ピクシブ百科事典, 중국 작품은 바이두 백과 등. 한국어 표기의 근거로는 쓰지 않는다. 읽은 것은 우리 말로 새로 쓴다(옮기지 않는다).
- 봇 확인 화면(Cloudflare 'Just a moment' 등)이 뜨면 풀지 말고 다른 곳을 쓴다.
- 위키백과는 `/wiki/<문서>`(원문은 `?action=raw` 를 붙여)만 쓴다. `/w/index.php` 는 robots.txt 가 막는다.
- 처음 여는 사이트는 **먼저 robots.txt 를 보고**, Claude 같은 자동 접근을 막는 곳이면 열지 않는다(워해머 때 게임즈 워크숍 한국어 사이트를 확인 전에 두 쪽 열었다). 스팀 도전 과제 한국어 화면(`steamcommunity.com/stats/<앱>/achievements?l=koreana`)은 공식 문자열이라 원자료로 쓸 수 있다. 그 화면이 글자를 스크립트로 그려 읽히지 않아도 **`api.steampowered.com` 은 쓰지 않는다**(robots.txt 가 모든 자동 접근을 막는다). 상점 쪽(`store.steampowered.com/app/<앱>/?l=koreana`)의 소개문과 도전 과제 칸을 쓴다.
- 한 명령 안에서 robots.txt 확인과 본문 받기를 함께 하지 않는다 — robots.txt 를 먼저 따로 보고, 허용될 때만 다음 명령으로 연다(첫 차례에 이렇게 해서 막힌 곳을 두 번 열었다).
- 임시 파일은 **스크래치 폴더 안에 작품 id 이름의 하위 폴더**를 만들어 쓴다(다른 조사와 파일이 겹치지 않게).
- 개념 사전에 없는 생각은 `concept_proposals` 에 올리되, `docs/concept_ideas.md` 에 이미 모인 생각과 같으면 그 이름을 그대로 쓴다.
