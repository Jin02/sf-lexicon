# SF 세계 후보 찾기 지침

SF 개념 사전에 넣을 **SF 세계**를 매체를 가리지 않고 빠짐없이 찾는다. 이번 일은 용어 조사가 아니라 **후보 목록**을 만드는 일이다.
레포 루트는 `C:\Users\jin0x\dev\sandbox\sf-lexicon`. 먼저 `CLAUDE.md` 와 `data/concepts.json` 을 읽는다(개념 id 를 쓴다).
맡은 갈래는 따로 알려 준다.

## 한 건 = 한 세계

- 후보 한 건은 **세계(같은 설정을 쓰는 작품 묶음)** 하나다. 시리즈·속편·같은 세계의 다른 매체 작품은 한 건으로 묶는다.
  (예: 소설이 영화가 되고 게임이 된 세계는 한 건. `media` 에 매체를 모두, `first_medium` 에 처음 나온 매체.)
- 다른 세계에 딸린 작품(스타워즈 게임, 에일리언 소설판 같은 것)은 따로 세우지 않는다. 그 세계가 목록에 없을 때만 그 세계를 한 건으로 세운다.

## 넣는 기준

- ★★2026-10-20 진님: **"지구상 이제까지 만들어진 sf 모든 작품을 찾아서 정리한다"** — 찾은 세계 목록은 **SF 전부**다. 매체(영화 포함)·주제(우주가 아니어도)·나라·시대를 가리지 않는다.
  - 우주 관련만·영화로 시작한 것 빼기·슈퍼히어로 빼기·마이너한 쪽 먼저는 **용어·로어 조사 차례**의 기준이다(`scripts/queue.py`). 목록에서는 빼지 않는다.
- **SF 가 바탕인 세계**: 우주, 미래 기술, 외계 생명, 인공지능, 유전자·몸 개조, 기술이 낳은 종말 뒤, 시간 여행, 평행 세계 등.
  판타지나 공포가 바탕이고 SF 를 조금 곁들인 것, 슈퍼히어로 세계, 단순한 근미래 배경은 넣되 `borderline: true`.
- 이름이 덜 알려진 것도 넣는다. 다만 정체를 확인할 수 있는 것(제목·해·만든 이가 자료에 있는 것)만. 지어내지 않는다.
- 세계관이 얇은 단편 한 편짜리도 넣되 `lore_size: "작음"`.
- 이미 목록에 있는 세계(`data/candidates_merged.json` 의 `worlds`)는 넣지 않는다 — 넣기 전에 원제·한국어 제목·지은이로 맞춰 본다.

## 많이 훑을 때 (세계 더 찾기)

- 목록 하나에 수백 곳이 나온다. **한국어판 여부는 한 건씩 검색하지 않는다.** 훑는 자료 자체(나무위키 문서의 정식 발매 정보, KOBIS·서점·상점 목록)에서 바로 알 수 있을 때만 적고, 나머지는 `확인 못 함`. 한국어 제목도 그 자료에서 확인될 때만(없으면 null).
- 세계관 한 줄은 훑는 자료를 읽고 우리 말로 새로 쓴다(60자 안쪽). 모르는 것은 지어내지 말고 자료에 있는 만큼만.
- `notability` 에는 그 세계가 들어 있던 목록(예: '휴고상 1975 장편 최종 후보 — 영어 위키백과')을 적는다.

## 후보 한 건

```json
{
  "id": "half_life",                 // 원제에서 딴 영문 소문자_밑줄
  "orig": "Half-Life",               // 원제(일본어·중국어·한국어 작품은 원어 그대로)
  "orig_en": "",                     // 원제가 영어가 아니면 영어 공식 제목
  "ko": null,                        // 정식 한국어 제목을 확인했을 때만(한국 작품은 원제). 못 찾으면 null
  "ko_src": null,                    // 그 제목을 어디서 봤나
  "media": ["게임"],                  // 소설 · 영화 · 드라마 · 애니메이션 · 만화 · 게임 · 탁상 게임 가운데 이 세계가 나온 것 모두
  "first_medium": "게임",
  "series": "Half-Life (1998) ~ Half-Life: Alyx (2020)",   // 무엇이 이 세계에 드나
  "by": "Valve",                     // 지은이·감독·만든 곳
  "year": 1998,                      // 이 세계가 처음 나온 해
  "country": "미국",
  "setting": "…",                    // 세계관 한 줄, 우리 말로 새로 쓴다(60자 안쪽)
  "concepts": ["teleport", "alien"], // 이 세계가 분명히 쓰는 개념 id(concepts.json 에 있는 것만, 확실한 것만)
  "new_ideas": "",                   // 개념 사전에 없는 눈에 띄는 생각이 있으면 한 줄
  "lore_size": "큼",                 // 큼 · 중간 · 작음 — 설정이 얼마나 두꺼운가
  "notability": "…",                 // 왜 넣나 — 확인한 근거 한 줄(판매·수상·시리즈 수·평가)
  "korean": {"status": "있음", "detail": "…", "src": "https://…"},
  "borderline": false,
  "videos": []                       // (있으면) 유튜브 영상 고리 — 아래 '영상 고리'
}
```

`korean.status` — 정식으로 한국어로 나왔나:
- 소설: 정식 번역 출간(출판사·해). 영화: 국내 개봉이나 정식 공개(정식 자막). 드라마·애니메이션: 정식 방영·정식 스트리밍. 만화: 정식 발간·정식 연재. 게임: 한국어 지원(스팀 상점의 지원 언어 표, 콘솔 공식 한국 사이트).
- 값: `있음` · `일부`(시리즈 일부만) · `없음` · `확인 못 함` · `한국 원작`.

## 영상 고리 (2026-10-22 진님: "유튜브 영상같은걸 찾을 수 있긴 할거야. 링크를 그냥 같이 걸어 줄 수 있어?")

조사하다 그 세계·작품·용어·로어 조각에 맞는 유튜브 영상을 보면 `videos` 칸에 건다(없으면 칸을 두지 않는다 — 억지로 찾지 않는다).

```json
"videos": [{"url": "https://www.youtube.com/watch?v=XXXXXXXXXXX", "what": "불가사의 완성 장면", "by": "채널 이름", "official": true}]
```

- **정식으로 올라온 것만**: 만든 곳·배급사·방송사의 공식 채널(예고편·소개·설정 영상)은 `official: true`. 게임 장면을 직접 찍은 영상, 설정을 풀어 주는 해설 영상처럼 올린 사람의 것이면 `false`. ★영화·드라마·애니메이션 **본편을 통째로 올린 영상은 걸지 않는다**(불법 업로드).
- 한 조각에 1~2개, 한 세계에 3개까지. 특정 장면이면 주소 끝에 `&t=123s`.
- `what` 은 무엇이 나오는 영상인지 우리말 40자 안(영상 제목을 옮기지 않는다), `by` 는 채널 이름 그대로.
- 줄거리 누설이 있는 영상은 그 항목이 `spoiler: true` 일 때만 건다(화면은 누설 보기를 켰을 때만 보인다).
- **찾는 길**: 웹 검색 결과와 위키백과·나무위키 문서에 이미 걸린 고리에서 주소를 얻는다. ★유튜브 검색 화면(`/results`)은 robots.txt 가 막는다 — 열지 않는다. 영상이 있는지·채널이 어디인지는 `https://www.youtube.com/oembed?url=<영상 주소>&format=json` 으로만 확인한다(막히지 않은 주소, 제목·채널 이름을 돌려준다). 영상 화면 본문을 긁지 않는다.
- `scripts/check.py`(작품·용어·로어)와 `merge_candidates.py`(찾은 세계)가 주소 꼴을 본다.

## 지킬 것

- **기억으로 채우지 않는다.** 특히 한국어로 나왔는지와 정식 한국어 제목은 한 건씩 찾아서 확인한다. 못 했으면 "확인 못 함" / null.
- 세계관 한 줄은 남의 글을 옮기지 않고 우리 말로 새로 쓴다. 쉬운 말로, 영어 낱말을 섞지 않는다(고유 이름은 예외).
- 개인 정보를 어디에도 보내지 않는다. 검색어와 공개 주소만 쓴다.
- 다른 파일은 건드리지 않는다. 커밋하지 않는다.

## 만들 파일

`data/candidates/<갈래 id>.json` — `{"group": "<갈래 id>", "candidates": [ … ]}`.
갈래 안에서 **빠짐없이** 찾는다. 기준에 맞으면 다 넣는다(갈래마다 대개 40~80건). 맡긴 글에 적힌 예시는 시작점일 뿐이니 그 밖의 것도 찾는다.
다른 갈래와 겹칠 법한 것도 넣는다(합칠 때 정리한다). 다 쓰면 파일이 올바른 JSON 인지 파이썬으로 한 번 읽어 확인한다.
